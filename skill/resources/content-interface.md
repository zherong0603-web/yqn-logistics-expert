# 物流专家与新媒体 IP 的内容接口

本文件是为用户目标设计的应用流程，**不是**原知识库自带的内容生产方法，也不作为仓颉 V1 原文方法论证据。物流专家负责业务事实、条件、反例与核验；人物项目负责真实经历、受众、观点、口吻和最终发布决定。

## 输入契约

- 目标读者与渠道：例如跨境卖家、新入职运营或海外仓客户；渠道和内容长度。
- 业务问题：一个明确场景，例如“订单已配货还能不能取消”。
- 人物素材：已核实的本人经历、观点或原话；若没有，保持中性专业表达。
- 发布范围：内部培训、客户沟通或公开内容；公开内容需要更严格的时效和保密核验。

## 先做事实卡

| 字段 | 要求 |
|---|---|
| 业务判断 | 用条件句，不把一条流程泛化为全部物流业务 |
| 依据 | 原文 ID、标题、页内章节、页面更新时间、本地档案位置 |
| 适用前提 | 系统、服务、承运商、仓库、订单状态、版本和客户条件 |
| 反例/例外 | 对应反例或冲突来源；无证据写“原资料未说明” |
| 当前核验 | 需要实时确认的报价、覆盖、仓库能力、禁寄、索赔、合同等 |
| 对外等级 | 可公开的方法 / 需脱敏的内部流程 / 不可未经确认对外表述 |

若关键依据缺失、来源冲突或结论依赖实时数据，事实卡状态为“待核查”，不能转为肯定式脚本。月结逾期风险阈值与内部审批链、客户专属价卡、系统 Token/接口配置、账号及打单凭据一律为内部核查资料；公开内容不得展示其数值、配置或截图。

## 再做选题卡

一个选题只讲一个可核验的业务判断，附一条最易犯的错误和一个具体处理动作。输出标题方向、开头问题、三段论证、可展示的证据、评论区可能追问、需要拍摄或授权的素材。客户姓名、订单号、收款信息、系统权限细节和未经授权的截图不进入公开稿。

## 内容验收

1. 每条业务事实都能回到事实卡和原页；数字、日期、服务范围单独核验。
2. “资料中如何操作”与“今天对客户承诺什么”明确区分。
3. 人物经历、客户故事、结果数据只来自已核实的 IP 素材，不由专家填空。
4. 面向不同 IP 时可重写表达和观点，但不能改变物流规则的适用条件。
5. 标题、封面或开头可能脱离正文传播时，需在同一传播单元标出 YQN 系统、面单来源、账单类型等关键前提；不要把单一归档流程写成通用行业规则。

原文入口见 [来源登记表](source-register.tsv)，冲突见 [来源冲突与时效风险](conflicts.md)。
